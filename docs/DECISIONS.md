# Implementation decisions for review

Spec v0.4 leaves these points open or undefined. Each default below is what the code does today. Items marked **iOS** are part of the client contract; items marked **Learning** change learner-visible behavior. Numeric defaults live in `src/config/policy.ts`.

## Challenge Map (Match Madness)

Built from `SYLL_MATCH_MADNESS_BACKEND_SPEC.md` v1.0 (proposed, not approved). Points that spec left open:

| Topic | Current behavior | Why |
| --- | --- | --- |
| Checkpoint gate **Learning** | Removed. Daily never gates new words, commits no longer open `checkpoint_challenges`, and `weeklySessionGoal` no longer resizes a challenge. Old challenges stay playable once; `/me/checkpoint-challenges` and `/me/journey` are deprecated, not removed | Spec §8.1–8.3 |
| Repeated Meaning on the board **iOS** | A queued pair is skipped while its Meaning is on the board or was matched in the last `minMatchesBetweenRepeats` correct matches; an empty board takes the head of the queue anyway. The client must mirror this rule | The spec's "never twice at once, 3 matches apart" can't be guaranteed by queue order alone, because the player picks which pair to match |
| Queue layout | Seeded SHA-256 shuffle. Level 1 takes 8 of the 12 core. Level 3 repeats the earliest queued Meanings, placed in the back half two slots apart | Deterministic and reproducible from `boardSeed` |
| Review picks | Up to 3 prior-chapter core Meanings in an order seeded by the new chapter id, skipping word/gloss collisions | Spreads review over all earlier chapters |
| Gloss | The published `meaningText` in the chapter locale, replaced by the learner's own override when present | A learner's edit stays in their own pool |
| Valid slot | Meaning has a live, unrecalled publication in the chapter locale, and is shared or still in the owner's personal list | Checked lazily on run issue. No trigger on recall or delete |
| `unlock` | Only reports a **first** clear. Replays report `none` + `open_map`; quit is `none` + `open_map`; fail is `none` + `retry` | Avoids re-announcing unlocks on replays |
| `chapter_ready` | Computed after the first clear of level 3, from the learner's current locale | Spec §6.4 |
| Expired runs | Not persisted mid-request (that would need a write outside the rolled-back transaction). Expiry follows `expires_at`; the next issue or the hourly job marks the row | Same rule as `learning_sessions` |
| Timing sanity | `endedElapsedMs` may exceed server time since `start` by at most `clockSlackMs` (5 s). No minimum gap between taps | Best effort only (spec §4) |
| `quit` endpoint on a started run | Settles as `committed` with outcome `quit`, empty events and no request hash, so a later commit conflicts | Spec §7 lists only `issued → abandoned` |
| Retention | `plan` and `events` cleared `eventsRetentionDays` (90) after commit or expiry; `result` and `commit_response` kept | Spec §5 default |
| Not implemented | `CHALLENGE_RATE_LIMITED` (no rate limiting yet), the start-from-another-device check (the API has no device id), redacting a just-deleted custom word from a live run's `status` payload, the `learn-home` challenge summary (the client calls `/me/challenge-map`), editorial pair blocklist, telemetry events | Out of scope or no infrastructure yet |

## Not implemented

- **Curation admin:** closed. `/admin/collections`, `/admin/topics` and `/admin/topics/:id/meanings` manage the catalog; see "Admin CRUD" below.
- **DB role separation (§12):** the app connects as `postgres`. Triggers protect snapshots, but a dedicated least-privilege runtime role is not set up.
- **Rate limits (§12):** event and audio sizes are capped; request rate limiting is not implemented. Custom word lookups that call AI have their own daily limit (`POLICY.customWords`).
- **Custom word reporting:** learners cannot report a wrong AI meaning.
- **Catalog audio:** ElevenLabs audio covers only words created through custom words; existing catalog words are not backfilled.
- **Metrics (§12):** logs carry `requestId`; the listed monitoring metrics and audit log are not implemented.
- **Recording abuse control (§4.2):** repeated `unavailable` events are accepted without limits.
- **C54 legacy prompts:** no legacy decoder, since no v0.2 data exists.

## Deviations from the spec SQL

- `id` columns are UUID v7 generated by the app, with no database default. Direct SQL inserts must supply `id`.
- Unique rules are unique indexes rather than constraints, with identical effect. FKs work the same.
- Added: RLS on all tables, and triggers blocking updates to `meaning_publications`, `learning_sessions.plan` and published `practice_items` content.

## Operational constraints

- Database session TimeZone must be UTC; the app refuses to boot otherwise.
- Drizzle ORM is pinned to 0.45.4 (stable `latest`); the 1.0 beta tags are not used.
- `embedded-postgres` runs tests on Postgres 17. Native `uuidv7()` is not used.

## Admin CRUD

Routes beyond spec §10 exist so an admin screen can browse and edit content. Rules:

| Topic              | Decision                                                                                                                                                                                                                                                                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Delete             | Only content never published. Published content is taken down with `recall` or `retire`, because learners may have studied it. Anything still referenced answers 409 `CONTENT_LOCKED`                                                                                                                                                          |
| Word identity      | `lemma` and `homographKey` are locked once a meaning was published or a learner owns one                                                                                                                                                                                                                                                       |
| Edit after publish | Meaning, pronunciation and example fields stay editable. What is live changes only on the next publish                                                                                                                                                                                                                                         |
| Private meanings   | Never listed outside `GET /admin/ai-meanings`, and every edit is refused, including `PUT .../locales/:locale`. They can only be approved or recalled, so approval always shares the stored AI text                                                                                                                                             |
| Practice items     | `PATCH` and `DELETE` are draft-only. Publish runs the same check the planner uses at serve time. A retired item cannot be published again                                                                                                                                                                                                      |
| Catalog            | The `personal` collection and owned topics are invisible to these routes. Only shared, live meanings can join a topic                                                                                                                                                                                                                          |
| Roles              | The `admin` role exists only on the account `pnpm db:seed` creates from the `SEED_ADMIN_*` env values. The API can grant or clear `editor` only, and refuses to change an account holding `admin`. `/admin/users` needs the `admin` role. A new role applies when that user's token refreshes. Changes are logged, since no audit table exists |
| Locales            | Admin `:locale` and `?locale=` accept only locales with copy in `locale-copy.ts`                                                                                                                                                                                                                                                               |
